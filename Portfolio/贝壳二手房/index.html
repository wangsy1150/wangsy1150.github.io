PROJECT 16 · 数据采集

贝壳二手房数据采集

针对贝壳找房二手房列表页的结构化采集工具：处理登录态、翻页与验证码，把房源信息落地为可分析的 Excel 表格。

Python Requests lxml / XPath 超级鹰验证码识别 openpyxl
采集结果落地：房源标题、总价、单价、户型、面积、楼层、朝向、小区、区域

项目背景

二手房价格数据是典型的「高价值但难拿」的数据：页面结构频繁调整、列表页需要登录态、翻页过程中还会触发滑块或图形验证码。 这个项目的目的不是写一个能跑一次的脚本，而是把采集链路做稳—— 让「打开页面 → 识别验证码 → 翻页 → 解析字段 → 存 Excel」这条流水线可以重复执行。

技术要点

登录态保持

Cookie 通过环境变量注入，避免把账号凭据写进代码或提交到仓库。

验证码识别

接入超级鹰打码平台，封装成独立 tools 模块，采集主流程只负责调用与重试。

XPath 解析

用 lxml 按列表卡片结构定位字段，字段缺失时降级为空值而不中断整轮采集。

数据落地

openpyxl 写出带表头的 Excel，并支持把房源图插入表格作为可视化附件。

执行流程

  • 初始化会话 — 从环境变量读取 Cookie，构造带 UA / Referer 的请求头。
    • >
  • 请求列表页 — 按区域与页码拼接 URL，逐页拉取房源卡片 HTML。
  • 验证码兜底 — 命中验证页时调用打码模块，拿到结果回填后重试当前页。
  • 解析与清洗 — XPath 提取字段，统一单位（万元 / 元每平），去掉空白与换行。
  • 写出文件 — 累加全部页结果，一次性写出 Excel 并打印采集条数摘要。

踩过的坑

Cookie 时效

登录态几小时就可能失效，脚本对「返回登录页」做了显式判断并给出明确报错，而不是静默返回空数据。

字段不稳定

不同小区的卡片字段数量不一致，解析时全部按「取不到就给默认值」处理，保证一条坏数据不毁掉整批。
