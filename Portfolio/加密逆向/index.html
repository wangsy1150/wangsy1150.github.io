网页接口加密逆向

我抓歌单的时候卡在这里：搜索接口的请求体里没有明文关键词，只有一串 params 和一串 encSecKey。改一个字就查不出东西， 抄一次 body 又只能查那一个词。所以我花了很久把这两串东西的生成过程拆开， 再用纯 Python 在本地一模一样算出来——现在是随便换关键词都能自己算，不是抄的。

说明：这里的 RSA 指数、模数和固定 AES 密钥，都是从页面 JS 的混淆代码里抠出来的常量， 属于逆向结果。搜索词只在你自己浏览器里参与运算，页面不会真的去请求网易云—— 真正打接口的那段在下面的 Python 代码里。

我为什么要把它拆开

搜索框里输入「周杰伦」，浏览器发出去的请求长这样： POST /weapi/cloudsearch/get/web， 请求体只有两个字段，都是 base64 / 十六进制串，看不出任何东西。 直接 requests.post 抄一遍 body 也能成功——但那是把结果抄下来，换个关键词就废了。

我第一版就是抄 body

把浏览器里的 params 抄进脚本直接发，确实能出结果。但换个歌手就得重新抄一遍—— encSecKey 里装的是那一次的随机密钥，抄来的东西天生只能用一次。

我怎么确认自己真的算对了

不看接口有没有返回——返回空也可能是别的原因。我拿同一个输入对页面真值做断言， 要求逐字节一致。差一个字节，接口就是空的，这一点没有中间地带。

难的地方跟我想的不一样

我原以为难在加密算法。其实算法是标准的，难的是那三个常量藏在混淆过的 JS 里—— 模数被拆成数组、用 emoji 做索引解码，直接搜十六进制串是搜不到的。

我是怎么一步步拆的

  • 先找到入口。我顺着搜索接口翻 JS，发现所有参数都从 asrsea() 这一个函数出——只盯它一个就够了。
  • 再把三个常量抠出来。固定 AES 密钥 0CoJUm6Qyw8W8jud、 IV 0102030405060708、RSA 模数与指数 010001。
  • 然后还原 AES 的两层。第一层用固定密钥，第二层用随机密钥； 都是 AES-128-CBC + PKCS7 + base64。
  • RSA 这一段最绕。它不是标准 PEM，是把 16 字节密钥补零到 126 字节后按小端拼成一个大整数，再模幂——我在这里对不上的时间最长。
  • 最后端到端验证。断言通过了我才敢拿去打接口，不然就是在瞎试。

关键代码

AES 一层只有四行，真正绕的是 RSA 那段「补零 → 小端 → 模幂」：

# AES-128-CBC + PKCS7，输出 base64（与页面 CryptoJS 一致） def aes_encrypt(text, key): key_b = key if isinstance(key, bytes) else key.encode("utf-8") cipher = AES.new(key_b, AES.MODE_CBC, IV) return base64.b64encode(cipher.encrypt(_pkcs7_pad(data))).decode("utf-8") # RSA：补零到 126 字节 → 小端拼大整数 → c = m^e mod n → 十六进制 def rsa_encrypt(text): bs = list(text.encode("utf-8")) while len(bs) % CHUNK_SIZE != 0: # CHUNK_SIZE = 126 bs.append(0) value = 0 for i, b in enumerate(bs): value |= b << (8 * i) # 小端：低字节在前 return format(pow(value, 0x10001, 0x00e0b509f625...), "x")

上面是课程提供的参考实现（netease_weapi.py），逐字节校验过。

我自己写的是调用它、把关键词变成请求的那一层，也是实际跑通的那一步：

# 输入歌手名 → 生成加密参数 → 直接 POST 拿真实结果 kw = input("请输入歌手名字:") r = weapi({"s": kw, "type": 1, "limit": 10, "offset": 0, "csrf_token": CSRF}) response = requests.post(url, headers=headers, data={"params": r["params"], "encSecKey": r["encSecKey"]}) print(response.text) # code 200 + 真实歌曲列表

Cookie 与 csrf_token 已脱敏——真实值属于账号凭证，不能贴到公开页面。

这一点说清楚，不含糊：三层加密的完整实现是课程提供的参考代码，我做的事是 跑通整条链路（关键词 → 生成参数 → 请求 → 拿到数据），并且用固定输入对页面真值 做断言确认逐字节一致。不是我从零手写的密码学实现——那需要另外的功底， 写了才叫虚报。

我踩过的坑

  • 我第一版只是抄 body。把浏览器里的 params 抄进脚本直接发， 能出结果，但换关键词就不行——因为 encSecKey 里装的是那一次的随机密钥。
  • 我一开始用标准库，怎么都对不上。换成 PyCryptodome 的 PKCS1_v1_5 怎么都对不上，因为它不是 ASN.1 结构，而是手写的补零 + 小端拼数。
  • 第二层该传字符串还是二进制，我搞反过一次。第一层输出是 base64 字符串，第二层要把它 当成文本再加密，不是当成二进制。
  • 常量藏在混淆里。模数被拆成数组、用 emoji 做索引解码， 直接搜十六进制串是搜不到的。

怎么运行

# 1. 装依赖 pip install requests pycryptodome # 2. 把 netease_weapi.py 和 demo03 放同一目录 # 3. 运行，输入歌手名 python demo03-ai获取歌单.py

输出是接口原始 JSON。我平时在打印前加一段写 CSV，落成表再看—— 调试加密参数的时候，直接打接口看返回，比读日志快得多。
