这条曲线不能当行情看。理由很硬：横轴是 10 次扫描，按代码里 schedule.every(5).seconds 算，全部跑完大约 50 秒。50 秒里同一件商品从 4480 掉到 1088、中间还反弹过两次 —— 真实市场不会这样。 这条线画出来的其实是"AI 每次从同一页里挑到的那个数字"，不是价格。

为什么整页丢给 AI

淘宝的搜索结果页 class 名是乱的、还天天变，写选择器就是在追着它改。所以我干脆不选：把整个 body 给模型，用五条规则约束它输出 JSON。省的是维护成本，赔的是稳定性。

为什么 JSON 一条条追加

每轮结果 append 进同一个文件，不覆盖 —— 这样才有历史可比。代价是文件会越来越长、同一商品重复一堆，画图前还得自己去重（下面第四个坑）。

为什么画图不用 CDN

原来那版用 Chart.js，要联网拉 CDN。搬到作品集里我改成自己用 SVG 画：不联网也能看，而且我能把第 9 次那个点单独标红 —— 这个标注比图本身重要。

我踩过的坑

1

同一链接，50 秒跌 3211 元 —— 这不是行情，是我的提取不稳

10 条记录里的 url 全都是同一个 id=1069191610233， 也就是同一个商品。价格却是 4299 → 4150.5 → 4480 → 3999 → 3728.8 → 3510 → 3266.25 → 2988 → 1088 → 1250。

我当时的规则是"取页面上最低的那个数字"。一个商品页上同时有原价、券后价、定金/首付、每期分期…… 模型每次读到的、觉得"最低"的那个数字不一样，于是曲线就"跌"了。 最贵的错误不是抓错，是把不稳定当成结论。

2

换了搜索词之后，7 次里 3 次直接返回 null

另一份 phone.json 里 7 条记录有 3 条是 null（点上面那个 chip 切过去就能看到断点）。 那是我在 prompt 里写的容错分支 —— "找不到商品或确定不了价格就输出全 null"。

问题是：我只写了"认输"，没写"重试"。主循环 while True 里 拿到 null 也照样存档，于是空数据混进了历史，画图时还得手动跳过。 正确做法是 null 当场重试一次、连续失败就告警，而不是记一笔空的。

3

它挑的"最低价"是个引流款

phone.json 那 4 次成功记录，价格全是 1088，标题是 "Huawei/华为 Mate 80 Pro新款正品鸿蒙mAtE70Pro官方官网直播手机" —— 一个标题里塞了三个型号关键词的店。 同一台 Mate 80 Pro 不可能 1088。

我的 prompt 只说了"价格最低"，没说"型号必须一致、标题不能堆关键词"。 规则写窄了，模型就会给你一个技术上正确、实际上没用的答案。

4

追加式存档，把"重复"存成了"历史"

每轮都 append，于是一个商品扫 10 次就有 10 条看起来不同的记录。 打开右边的开关「同一个链接只算一次」能看到真实情况：10 条记录 = 1 个商品 = 1 个价格。 所谓"监控了 10 次"，其实一次都没换过对象。

有一件事我只能说"我猜"，不能说"我查到"。 上面第一条我给的因果是"页面上有多个价格数字，模型每次挑到的不一样"。这是最合理的解释， 但我当时没有把那一轮的页面 HTML 存下来，所以这只是推断，不是证据。 要验证得重跑一次、把 body 一起落盘再比对 —— 我记在这儿，没验证就不写死。

边界：哪些是我做的

这套五段式结构（猪八戒 → 猴哥 → 沙和尚 → 唐僧）和 prompt 的骨架是照着现成套路搭的， 不是我从零设计的架构。
属于我的是：① 按这段代码真跑出来的两份数据（10 条 + 7 条，都在仓库里）； ② 上面四个问题，是我自己盯数据盯出来的，没人替我把它们总结好； ③ 这一页的曲线、预警器、去重开关，是我为了把问题说清楚重新写的，没引 CDN。
还有个更大的实话：这个"监控"其实没在监控任何东西 —— 它扫的是搜索结果页，不是商品详情页； 没有价格历史基线，也没有通知。真正的价格监控应该是每天固定时间扫一次、只扫自己收藏的那几个商品、跌了才叫我。
