对齐出来的结论：三版的功能骨架是同一个 —— 蓄力、抛物线、镜头、落地回弹、排行榜、挂机，一个没少。 真正差的只有两处，都在「看得清不清」上：方块是平涂的，没有体积；下一块没有目标标记。 这两处我原来以为无所谓，把三版并排截图才看出来 —— 平涂块看不出「这是个能站上去的墩子」。

所以补了这两处，其余没动

① 方块从平涂改成伪 3D

加了一层 11px 的透视厚度：顶面提亮、右侧压暗，正面保留原来的上亮下暗渐变。

② 下一块打白色虚线框

告诉眼睛「这一跳要落这儿」。原来只能靠估，现在有明确的落点参照。

③ 原始那一份留着没删

改的是我复制出来的 小游戏合集/demo/jump.html，仓库里最早那版原样保留，随时能回去对照。

// 侧面压暗 + 顶面提亮，就是这两块让方块「立起来」 function drawBlock(b, isTarget) { const x = b.x - cameraX, y = b.y - cameraY; // 右侧暗面：从正面右上角往右后上方拉一个平行四边形 ctx.beginPath(); ctx.moveTo(x + b.w, y); ctx.lineTo(x + b.w + DEPTH, y - DEPTH); ctx.lineTo(x + b.w + DEPTH, y + b.h - DEPTH); ctx.lineTo(x + b.w, y + b.h); ctx.fillStyle = 'hsl(' + b.hue + ',62%,40%)'; ctx.fill(); // 顶面亮面：同理，往左后上方拉 ctx.beginPath(); ctx.moveTo(x, y); ctx.lineTo(x + DEPTH, y - DEPTH); ctx.lineTo(x + b.w + DEPTH, y - DEPTH); ctx.lineTo(x + b.w, y); ctx.fillStyle = 'hsl(' + b.hue + ',78%,80%)'; ctx.fill(); // 目标块：白色虚线框（画在正面内侧 3px） if (isTarget) { ctx.strokeStyle = 'rgba(255,255,255,0.85)'; ctx.lineWidth = 2.5; ctx.setLineDash([7, 5]); ctx.strokeRect(x + 3, y + 3, b.w - 6, b.h - 6); } } // 调用处：blocks[1] 就是「下一块」，只有它打框 blocks.forEach((b, i) => drawBlock(b, i === 1));

这段是这次唯一动过渲染逻辑的地方；蓄力映射、镜头、回弹、排行榜、挂机一行没改。

2048：查出来是重复的，所以没有第二份

2048 我做过两套。对齐之后发现另一套只是多了「悔一步」和「最高分」两个小功能， 主体（棋盘合并、滑动动画、AI 搜索）完全是一回事。再复制一份出来没有意义， 那只是让作品集里多一个同款。所以只留一个入口。

「悔一步」和「最高分」暂时没并进来 —— 我认这是缺口，已经登记，不是忘了。

三件这次才想明白的事

  • 1 行数不是好坏。现在这版 1134 行，第一版 1698 行，差的 500 多行主要在 CSS 变量和注释上，功能骨架一模一样。拿行数比谁强，是自欺。
  • 2 手感差一点，玩起来差很多。平涂块和 3D 块的差别，静态看不出来， 手指按下去那一下就知道 —— 有没有体积感，决定了你敢不敢算那一跳。
  • 3 先查自己的旧代码。动手写第三遍之前，先确认前两遍有没有能用的 —— 这次两处改动，全是从旧版里挑出来的，一行新逻辑都没发明。
