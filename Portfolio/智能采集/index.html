这些都是真的。数据来自 guazi.csv —— 用 demo03-瓜子二手车.py 实际跑出来的 40 条，我把它压成一份内嵌数据，只做了筛选 / 搜索 / 排序。 图片链接指向对方 CDN 且会失效，所以列表里没有放图。

我为什么把手写选择器换掉

我抄的选择器碎过

.hotsearch-item 这类选择器我抄过一版，跑通了挺高兴。结果站方改了一次 class，全部失效， 规则和页面绑得太死，我改不动。

后来变成「改那句话」

字段漏了不用回去翻 HTML。我第一次只写了「标题、售价」，发现少了年份和里程， 就把那句话补全，让它重新生成一遍——比改代码快得多。

其实还是 CSS 在干活

我一开始以为模型在逐条读页面，那样又慢又贵。不是——它只负责写规则， 真正提取还是 CSS 选择器在跑。所以快、稳，不用每次请求都问模型。

我是怎么串起来的

  • 先决定浏览器怎么开。headless=True 不开窗口， 我调规则的时候把它设成 False，能看着它点，出问题一眼就看见。
  • 再把那句话翻译成规则。传 URL + 一句 instruction， 模型读一遍页面结构，吐一份 JSON schema 出来。
  • 然后拿着规则去跑。缓存、等待超时、提取策略都在这层配—— 这几个参数我调了最久。
  • 最后落成 CSV。res.extracted_content 是个 JSON 字符串， json.loads 之后 pd.DataFrame 直接写文件。

关键代码

# 1. 只描述「要什么」，不写选择器 strategy = JsonCssExtractionStrategy.generate_schema( url=url, llm_config=LLMConfig(provider='deepseek/deepseek-chat', api_token=os.getenv("DEEPSEEK_API_KEY")), instruction="提取页面所有二手车信息，每条数据包含：车辆标题、售价、" "上牌年份、行驶里程，只返回车辆列表，过滤广告无关内容" ) # 2. 拿这份 schema 当作运行时的提取策略 run_config = CrawlerRunConfig( cache_mode=CacheMode.ENABLED, wait_for_timeout=3000, extraction_strategy=JsonCssExtractionStrategy(strategy) ) # 3. 抓完直接落表 async with AsyncWebCrawler(config=browser_config) as crawler: res = await crawler.arun(url=url, config=run_config) data = json.loads(res.extracted_content) pd.DataFrame(data).to_csv('guazi.csv', index=False, encoding='utf-8-sig')

这段是 demo03-瓜子二手车.py 的主体，实测能跑通并落出 40 行。

utf-8-sig 这个细节不是随手写的。 用 Excel 打开普通的 utf-8 CSV，中文会变乱码——因为 Excel 默认按 GBK 读， 而带 BOM 的 utf-8-sig 它会认。这个坑我在别的项目里踩过一次。

我踩过的坑

  • 我以为 schema 生成一次就能一直用。不是。换个站点、甚至同站改版， 规则就可能抓空。要么重新生成，要么把 schema 存下来做版本管理。
  • 等太短只能抓到空壳。我第一版拿到 0 条，还以为是规则写错了。 其实是列表靠 JS 渲染，wait_for_timeout=3000 是因为列表靠 JS 渲染，不等就只剩骨架。
  • 广告混在列表里。我过滤出来发现有台「车」的价格明显不对， 点进去是推广位。所以 instruction 里那句「过滤广告无关内容」不是凑字数的。
  • 缓存骗过我一次。CacheMode.ENABLED 省时间， 但调规则的时候得临时换成 BYPASS——不然改了规则也看不出变化， 我在这上面浪费了不少时间。
