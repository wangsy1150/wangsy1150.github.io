项目背景

常见语音助手只能「问一句答一句」，答案对不对全靠模型自由发挥。这个项目想验证另一条路： 把本地文档交给 AI 当资料库，让它自己判断什么时候该去查、什么时候不该查， 并且把「查没查、查到什么、来源是哪个文件」全部暴露出来。整条链路 listen → think → speak 三层互不依赖，任何一层都能单独替换或测试。

技术要点

Function Calling 真自主

请求体带 tools + tool_choice:"auto"，闲聊不查库，问事实才调工具 —— 决策权在模型手上。

诚实性三重保险

系统提示词约束 + 工具结果里再强调一遍 + 一致性校验：没查就下结论时系统替它补查再重答。

朗读自动降级

edge-tts 在线合成失败时，自动回退到浏览器原生 speechSynthesis，对话流程完全不中断。

服务端记忆

按 session_id 隔离，保留最近 10 轮；刷新页面、甚至重启后端上下文都还在。

零依赖中文检索

只用标准库实现二元组切词 + BM25 风格 IDF 打分，另有单字兜底与文件名入词表。

不侵入老代码

v3 的新接口全部走 Flask Blueprint，原有路由一行没改，老测试 102 个用例全绿。

一次问答发生了什么

  • 听 — 浏览器 SpeechRecognition 把语音转成文字（listen）。
  • 决策 — decide() 带上工具箱请模型做一次判断：调工具，还是直接回答。
  • 调用 — 模型说要查，run_tool() 就在本地知识库检索，把命中片段塞回对话。
  • 再决策 — 带着观察结果回到第 2 步，最多 3 轮；到上限则强制收口回答。
  • 校验 — 若模型全程没查却断言「查不到」，系统自动补查一次并让它重新作答。
  • 说 — 回答交给 edge-tts 合成朗读，同时把整条 trace 渲染成决策卡。

关键代码结构

# agent_core.py —— 交给模型的工具说明（节选，真实文案） SEARCH_TOOL_DESCRIPTION = ( "在用户上传的本地知识库（.md / .txt 文档）中做相关性检索……" "【什么时候必须调用】当用户的问题涉及事实、定义、数字、流程、政策、规则时，" "必须先调用本工具，不要凭自己的记忆回答。" "【返回什么】如果片段列表为空，说明知识库里没有这部分资料，" "此时必须如实回答「资料里没有提到」，绝对不要编造。" ) # 工具箱：一个工具一项，这份说明会原样发给模型 TOOLBOX = [{"name": "search_knowledge_base", "description": SEARCH_TOOL_DESCRIPTION, ...}]

模型能否正确判断「该不该查」，全靠这段说明 —— 所以它写得足够具体。

# 一轮 Agent 对话（ReAct 风格结构示意，实现见源码 agent_core.py） messages = build_messages(text, history) for step in range(AGENT_MAX_STEPS): # 最多 3 轮决策 decision = decide(messages, tools=TOOLBOX, tool_choice="auto") if decision.action == "final": break result = run_tool(decision.name, decision.arguments) # → 检索本地知识库 messages.append(observation(result)) # 片段塞回对话 else: decision = decide(messages) # 到步数上限：强制收口 # 一致性校验：没查过就说「没有」，系统替它补查再让它重答 if decision.says_not_found and not trace.has_tool_call and kb.has_documents(): messages.append(observation(run_tool(SEARCH_TOOL_NAME, {"query": text}))) decision = decide(messages)

真实案例：问「我们几点下班？」模型一度直接答「资料里没有提到」，补查后它才正确回答「下午 18:00 下班」。
