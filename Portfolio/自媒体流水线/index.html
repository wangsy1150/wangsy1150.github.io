我为什么把它做成流水线，而不是写个脚本

一开始我不是这么想的

最初我只想要"一键发知乎"。写完发现真正耗时间的不是发布那 30 秒，是前面两小时刷热点和纠结写什么。所以我把最上游的采集也拉了进来，整条链才省时间。

三个平台起才叫验证

SOP 里我给自己定的是"至少三个平台热点 + 两个平台交叉验证"。这次只通了两个平台，我拿 B 站的热搜榜和排行榜当两路分开算，跨平台的那两个话题我认，同平台互证的不认。

最后一步永远是手动

它能一路跑到"已存草稿"，然后停住。不是做不到自动发布，是我不想让一个我没看过的东西带着我名字出去。

第二步我很怕：字数规矩自己都守不住

SOP 里我给写稿定了死规矩：标题 18–28 字、正文 600–1000 字、来源 2–3 条。 规矩写下来容易，写的时候没人盯着就飘。所以我做了一个实时校验器——下面填的是我 9 月 8 日真发出去的那篇，你可以改任意一个字符，看它怎么翻红。

发布这段：它靠什么找到知乎的输入框

知乎的编辑器是 Draft.js，标题是个 textarea， 正文是个 contenteditable 的 div——直接 fill() 填不进去， 得先点一下、再 keyboard.type() 一个字一个字敲。 我把所有定位都单独放一个文件，每个位置先按语义找、再按 CSS 兜底：

TITLE
标题输入框 · 4 个候选，第一个命中就用
  1. textarea[placeholder*='请输入标题']
  2. textarea[placeholder*='标题']
  3. textarea.WriteIndex-titleInput
  4. .WriteIndex-titleInput textarea
BODY
正文区 · Draft 的 contenteditable，得先点再敲
  1. .public-DraftEditor-content[contenteditable='true']
  2. .ProseMirror[contenteditable='true']
  3. div[contenteditable='true'][role='textbox']
  4. div[contenteditable='true'][data-contents='true']
TOPIC_INPUT
话题搜索 · 弹窗里的输入框，跟页面上的不是同一个
  1. input[aria-label='搜索话题']
  2. [role='dialog'] input[placeholder*='搜索话题']
  3. [role='dialog'] input[placeholder*='话题']
  4. input[placeholder*='添加话题']
PUBLISH_TRIGGER
发布入口 · 三个按钮长得一样，位置不同
  1. button:has-text('发布文章')
  2. button.PublishPanel-triggerButton
  3. button:has-text('发布')
  4. button:has-text('确认发布')

踩过的顺序问题：先按语义找，语义失效再退回 CSS。 反过来不行——知乎改版一次，写死的 CSS 全废；而"输入框的 placeholder 是'请输入标题'"这种事，三五年都不太会变。 第一个候选我标红了，那是首选，后面三个是备胎。

我踩过的坑

1

标题忘了换，我真发出去一篇叫「测试文章」的

跑通那晚我把一整篇写得好好的《我用AI开了一家24小时不打烊的自媒体餐厅》配了个标题「测试文章」就发出去了， 因为命令行里 --title 我图省事没改。

发现的时候已经发布了。这张截图是我当时存的报错页，浏览器标签上写着 (2 条消息) 测试文章 - 知乎—— 标题错了，内容是对的。后来我没删，留着提醒自己：自动化最危险的地方不是它做错，是它做对了你没看的那一项。

2

cookie 20KB，不能进仓库

登录状态存在 .zhihu-state/creator.json，20,600 字节，里面是账号凭证。 这个文件一旦被提交上去，等于把账号送人。所以 .gitignore 第一行就得写它。

跟上次做网易云那个项目是同一个教训：凭证永远不进代码。

3

四个平台，只有两个能通

SOP 写的是"至少成功获取三个平台热点"。这次为了做这个页面我重新采了一遍： 微博的 JSON 接口直接 403 Forbidden，只能抓 HTML 榜单页；知乎的热榜接口回的是"身份未经过验证"； 小红书要登录态。真正常的只有 B 站。

所以统计块里那个「2 个」不是我谦虚，是实话。这次我也没凑——缺平台就在页面上写缺，不假装四个都通。

4

第一版交叉验证会把不相干的东西凑成一对

我用二元组重合来判"两个平台的同一条热点"，结果第一版跑出来 人工耳蜗里的声音是什么样的 ↔ 现实夜之城什么样 被判成一对——只因为都含"什么""么样"。

加了停用二元组（什么 / 么样 / 是什 / 样的）之后这对就消失了。阈值和停用词不是玄学，是不加就一定会出假阳性。

边界：哪些是我做的，哪些不是

发布器（zhihu-auto-publisher）是课程给的成品，不是我写的。 509 行 publisher.py + 那套选择器，我改的是参数、跑的是链路。
真正属于我的是三件：① 那份 SOP（operate-zhihu 这个 skill：采集→互证→选题→写稿→发布，每一步的硬规矩）； ② 把采集和发布接起来，让它能一条命令跑完；③ 上面那个标题没换的事故——是我真操作失误的。
页面里那篇文章是 Agent 按 SOP 出的初稿、我审过之后按下的发布，所以署名是我的，文字不是我一字一字敲的，这点我不含糊。
