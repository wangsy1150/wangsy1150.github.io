GitHub Trending 智能巡检

我每天早上都会刷一遍 Trending，但一页 25 个项目，光看名字和一句话描述 根本判断不出值不值得点进去，半小时就这么没了。所以我把它做成了一个 Skill： 抓榜 → 交给 AI 逐条打分 → 只把过线的写进报告，剩下的连看都不用看。

让 AI 稳定吐 JSON 的关键：提示词分四层写 这是我这份 prompt 里最想让人看的部分
LAYER 1

角色定位

「严谨的资深技术项目评估专家」——先把语气定下来，它就不会写得像广告。

LAYER 2

评估规则

0–10 分、值不值得学、理由要结合描述语言 Star、适合什么水平——四条一起要。

LAYER 3

输出格式 + 范例

给完整 JSON 范例，并明说「不要 markdown 代码块」。不给范例它就会加一堆解释。

LAYER 4

容错处理

信息不够就返回 null 并写「信息不足」，不许编。这条是给评分兜底的。

# 第四层，容错处理（原文） 如果某个项目的信息缺失（例如没有描述、语言未知），或者无法判断其学习价值，不要编造信息。 对应的“分数”和“值不值得学”字段返回 null，并在“理由”中说明“信息不足，无法评估”。

我为什么要做它

榜单本身不解决问题

Trending 给的是「今天涨得快」，不是「这跟我有关系」。一页 25 个，我真正会点开的不超过两个。

我不想每天重来一遍

判断标准是固定的：描述清不清楚、技术栈我用不用得上、Star 是真热度还是刷的。 既然是固定标准，就该交给机器。

做一次，以后一句话就能跑

所以我不是写了个脚本，是打包成一个 Skill： SKILL.md 说清流程和文件放哪，脚本只负责干活。

整个流程我拆成了八步

  • 抓榜。DrissionPage 打开 github.com/trending， 每个 article.Box-row 取标题、描述、语言、Star、链接五样。
  • 落原始数据。先存成 raw.json，不管后面评分成败， 原始抓取结果一定留得住。
  • 补全链接。页面给的是 /owner/repo 相对路径， 要补成完整地址，并抽出 OWNER/REPO 给读 README 用。
  • 逐个读 README。一个项目一次请求，不把所有 README 塞进同一个上下文—— 塞进去要么超长，要么让模型串味。读不到就标「README 缺失」。
  • 逐条评估。交给 AI 打分，要求只吐 JSON。解析失败就让它重吐一次，最多一次。
  • 阈值过滤。分数 ≥ 阈值的进报告，其余只留数量统计。这一页的滑块就是这一步。
  • 生成日报。按模板落成 Markdown，存进 reports/。
  • 回报结果。报告路径 + 抓了多少 + 过了几条 + Top 3 的标题分数链接。

关键代码

抓取那段是我按 GitHub 现在的 DOM 写的，五个字段各一条 XPath：

# 每个 article 就是一个项目卡片，五样东西全在里面 ps = page.eles("xpath://article[@class='Box-row']") for p in ps: title = p.ele("xpath:.//h2[@class='h3 lh-condensed']").text jieshao = p.ele("xpath:.//p[@class='col-9 color-fg-muted my-1 tmp-pr-4']") yuyan = p.ele("xpath:.//span[@class='tmp-mr-3 d-inline-block ml-0 tmp-ml-0']") star = p.ele("xpath:.//a[@class='tmp-mr-3 Link Link--muted d-inline-block']") link = p.ele("xpath:.//h2[@class='h3 lh-condensed']/a[@class='Link']").attr("href") # 描述和语言可能没有（有的项目就是空的），取不到给兜底值，不能让整个循环崩 xiangmu.append({ "title": title, "jieshao": jieshao.text if jieshao else "无介绍", "yuyan": yuyan.text if yuyan else "未知", "star": star.text if star else "0", "link": link })

然后一次性把整批交给 AI，中间那段四层提示词才是关键：

prompt = f""" 第一层，角色定位： 你是一个严谨的资深技术项目评估专家。…… 第二层，评估规则： 1. 综合评估项目的流行度、描述完整度、技术栈，给出一个 0-10 分的学习价值评分（保留1位小数）。 2. 判断该项目"值不值得学"（输出：值得 / 不值得 / 视情况而定）。 …… 第四层，容错处理： 如果某个项目的信息缺失……不要编造信息。 对应的"分数"和"值不值得学"字段返回 null，并在"理由"中说明"信息不足，无法评估"。 待评估的数据如下： {json_str} """

我踩过的坑

  • 让它「输出 JSON」，它就给你套个 markdown 代码块。第一版我直接 json.loads()，十条里挂九条。改成第三层明写「不要包含 markdown 代码块标记」 并给一份完整范例，才稳定下来——给范例比给要求管用。
  • 没有描述的项目会让整批一起崩。有的 repo 简介是空的， .text 直接抛异常，整个 for 循环断在那儿。后来每个字段都加了 if ... else 兜底。
  • XPath 写死 class 是要还的。GitHub 改过一次列表结构， 我第二天抓到 0 条。现在我会先确认 article.Box-row 还在不在， 不在就直接告警，而不是安静地返回空列表。
  • 只看 Star 会把资源库当技术项目。这次抓到的一个电子书合集 2.3 万 Star、日增 227，按热度排它很靠前，但它本质是个链接汇总， 技术上没东西可学。它拿了 4.5 分，被阈值挡住了——这正是加 AI 评分的原因。
  • 脚本和文档要对得上。我的 SKILL.md 写的是完整八步， 但脚本只实现了「抓取 + 一次批量评估」。逐个读 README 那一步我没在脚本里做完， 所以这里出现的分数是基于标题、描述、语言、Star 打的，没有读 README。 这条我不想含糊——文档写得比代码全，是实话。

怎么跑

# 环境变量：Key 必填，其余可选 export DEEPSEEK_API_KEY="你的 key" export SCORE_THRESHOLD="7.0" export DEEPSEEK_MODEL="deepseek-chat" # 建目录 → 跑抓取 → 看报告 DATE=$(date +%F); mkdir -p data/readmes/$DATE reports python scripts/github智能巡检.py # 产出 data/github-trending-$DATE.raw.json data/github-trending-$DATE.evaluated.json reports/github-trending-$DATE.md

这一页的 10 条分数，是我用同一套四层提示词真调 deepseek-chat 打出来的： 8508 ms，2746 tokens。项目数据是 github.com/trending 当天页面的真实内容——但只有 10 条：我这次走的是网页读取通道，一次只回得来页面开头那一屏； 脚本正常跑（DrissionPage 直接取 DOM）会抓到整页 25 条。这一点我写在页面上，不凑数。
